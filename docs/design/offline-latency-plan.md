# 降低「离线（内核）渲染」延迟的具体清单

**背景**：用户实测「离线渲染延迟卡顿比服务器渲染更厉害 ✗」，因此**默认已切到服务器渲染** ✓
（`viewer-app.js` 的 `serverRenderPreferred()` 默认 `true` ✓，可用勾选显式回到内核 ✓）。
**本文件给出后续降低离线延迟的具体做法 ✓**，并给出**服务器端已量化的三档延迟**作为目标基线 ✓。

## 一、服务器端三档延迟（**实测 ✓，可复跑 ✓**）

**方法**：4 层 1024² 文档，子区域 512²，`raw: true`（**直通 ⇒ 不含 PNG 编码 ✓**）；
**默认模式 vs `YANSHI_SKIP_REGION_CACHE=1`** 两组对照 ⇒ **∴ 外层与内层各自的贡献可分离 ✓**。

| 档 | 延迟（中位） | 相对冷 | 结论 |
|---|---|---|---|
| **① 冷（**全 miss**）** | ≈ 46–58 ms | 1.0× | 基准 |
| **② 热（**外层块缓存命中**）** | **9.9 ms** | **≈5.8×** | **最省 ✓** |
| **③ 改顶层（**内层 tile 命中**）** | **48.8 ms** | **≈1.2×** | **次省 ✓** |

**判据**：`scripts/tool-latency-tiers.mjs`（**断言 `② < ③ < ①` ＋ `② ≤ ③ × 0.6` ✓**；
**变异**：`YANSHI_SKIP_REGION_CACHE=1` ⇒ 必红 ✓）。

## 二、内核应照搬的四件事（**按收益排序 ✓**）

| # | 照搬什么 | 服务端的对应物 | 预期收益 | 代价（**两面 ✓**） |
|---|---|---|---|---|
| **1** | **整块（**请求级**）缓存** | `Document::region_cache` ＋ `region_fingerprint` | **≈5.8×**（**最大 ✓**） | **内存 ↑（**按区域存 ✓**）｜指纹要覆盖**对象数据**，否则会**复用旧像素** ✗ |
| **2** | **免编码直通** | `raw: true`（**直接给 RGBA8 ✓**） | **省掉 PNG 编码 ✓**（**大区域上占显著比例 ✓**） | **带宽 ↑（**未压缩 ✓**）⇒ **∴ 本地／同源场景才合适 ✓** |
| **3** | **tile 级合成缓存** | `BelowTiles`（**按 tile 存 ✓**） | **≈1.2×**（**在"改顶层"时 ✓**） | **内存 ↑（**4K 一份 ≈33 MB ✗**）⇒ **∴ 必须配**块数上限 ＋ LRU ✓** |
| **4** | **脏区渲染** | `render_region(bbox)` ＋ `region_fingerprint` | **只算改过的区域 ✓** | **需要**脏区跟踪 ✗**（**内核已有 tile 化 ✓ ⇒ 可复用 ✓**） |

## 三、**必须同时带上的正确性约束**（**否则会"快而撒谎" ✗**）

1. **指纹必须覆盖对象数据** ✓ —— 否则"改了像素却命中旧合成" ✗
   （**服务端曾出现此风险 ✓，已由第 561 轮加的签名比较兜住 ✓**）。
2. **命中必须比较签名** ✓ —— **只看"这批 tile 在不在"是不够的 ✗**
   （**服务端缺陷 ✓，第 561 轮修复 ✓**）。
3. **凡改像素的入口 ⇒ 必须失效所有依赖像素的缓存** ✓
   （**服务端教训 ✓：只失效 tile 缓存 ⇒ 差 18.75% ✗**）。
4. **不许把"没跑"当"通过"** ✓ —— **统计型判据必须同时核对**跳过数量 ✗**
   （**服务端教训 ✓，第 566 轮修复 ✓**）。
