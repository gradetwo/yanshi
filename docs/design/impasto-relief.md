## 二、已经查清的关键事实（下一轮不用再查）

1. **滤镜是渲染器内部按名字应用的**：`render.rs:2741 / 2901 / 3206` 调
   `FilterKind::from_name(name)` ＋ `apply_filter(buffer, name, params, opacity, canvas)`
   => **只要给 `FilterKind` 加一个变体，整条链路就自动接上**（不需要新工具、不需要改 spec）。
2. **要补三处**（漏一处就编译不过，本轮实测）：
   * `enum FilterKind` 加变体；
   * `FilterKind::from_name` 加名字（建议 `"relief" | "emboss" | "impasto"`）；
   * `FilterKind::name()`（`match self`，`filter.rs:157` 附近）加一行 —— **这处最容易漏**（E0004）。
   * 再在 `apply_filter` 的 `match kind` 里加分支（读 `params`，与 `Sharpen`/`Noise` 同形）。
3. **`Buffer` 的读写口径**（本轮踩到）：
   * `Buffer::pixel(x: u32, y: u32) -> LinearRgba`（**u32**，不是 usize）；
   * **没有 `set_pixel`** => 写回要用 `buffer.pixels_mut()`（裸 `&mut [f32]`，每像素 4 个分量）；
   * 读快照用 `buffer.pixels().to_vec()`（法向必须基于**同一时刻**的高度）。
4. **高度从 alpha 来**：一层里每个笔触的 alpha 就是"这里堆了多少颜料" => 浮雕看**相对高差**，
   取 alpha 作高度是自洽的；**只处理 `alpha > 0`** 的像素，邻居空白时按"同高"处理
   （否则会把笔画边界当成坡面）。

## 三、算法（本轮已写到可编译）

```text
h = alpha（可乘 height_gain，缺省 1）
n = normalize(-gain·dh/dx, -gain·dh/dy, 1)          // 中心差分
l = (cos e·cos a, cos e·sin a, sin e)               // azimuth 0°=+x；elevation clamp 1..89°
rgb' = rgb · (1 + strength · (n · l))               // strength 缺省 0.6，clamp 0..4
```
`params` 读法（与既有滤镜同形）：`azimuth`（缺省 135）、`elevation`（45）、`strength`（0.6）、`height_gain`（1）。

**根因是我的测试造错了样本**：我用的是**线性坡面**（alpha 从左到右线性升高）=> **每一点斜率相同**

**正确的样本是"隆起"（钟形 alpha）**：它才有"**迎光坡 vs 背光坡**"的对比 ——
光从右侧时右坡（法向朝右、迎光）应当更亮，光从左侧时相反。本轮已经把测试改成隆起版并跑过一次，

## 六、★ 第 254 轮实测：`strength` 的可用范围，以及一个**设计缺陷** ★

**实测（400×300、软边厚涂堆、`height_gain: 24`、方位 135／仰角 45）**：

| `strength` | 画面均值 | 相对 | 标准差（对比） | 相对 |
|---|---|---|---|---|
| 0.0（对照） | 240.6 | — | 37.8 | — |
| 0.5 | 242.5 | +1.9 | 32.7 | −5.1 |
| 1.0 | 244.1 | +3.5 | 28.4 | −9.5 |
| 2.0 | 246.9 | +6.3 | 21.2 | −16.7 |
| **5.0** | 251.7 | **+11.1** | **11.4** | **−26.4** |
| 10.0 | 252.0 | +11.3 | 10.8 | −27.1 |

**可用范围**：**0.3–2.0** ✓（0.5 轻微、1–2 明显）。**≥5 就过曝** ✗ ——
表现是**整体被提亮**（均值 +11）而**对比反而塌掉**（标准差 −70%）✗。

**根因（我自己的设计缺陷 ✗）**：明度偏置用的是 `factor = 1 + strength·(n·l)`，
而 `n·l` 里含**常数环境项** `l_z = sin(elevation) ≈ 0.707` ⇒
⇒ 每一项都被乘上 `1 + 0.707·strength` ⇒ **一律提亮** ✗（不是只有迎光坡提亮 ✓）。
`strength = 10` 时那个因子是 8.07 ⇒ 直接饱和 ✓。

**修法（第 254 轮已做 ✓）**：把**同一归一化下的平面响应**减掉 ——
`tilt = dot − light[2]/norm`（数学上**正好等于纯坡面项** `(nx·lx + ny·ly)/norm` ✓）
⇒ 平面处恒为 0 ✓、斜坡处只反映迎光/背光 ✓ ⇒ `strength` 只控制**浮雕强弱** ✓。
**两次踩坑（判据当场抓住的）**：
  1. 第一版减的是 `light[2]`（不是 `light[2]/norm`）⇒ **过度修正**：倾斜面上 `norm > 1`
     ⇒ `lz/norm < lz` ⇒ 平均 `tilt` 变负 ⇒ 均值 0.5000 ⇒ **0.2841**（变成整体**压暗** ✗）；
  2. 判据容差第一版写成 `<= 2.0`，而 luma 是 **0..1** 单位 ⇒ 等于**不设限** ⇒ 判据**假绿** ✗
     （收紧到 0.05 后立刻红 ✓）。
**判据**：`crates/yanshi-render/src/filter.rs` 的 `relief_ambient_tests` ——
① `strength = 5` 与 `0` 的**均值差 ≤ 0.05** ✓（修前 0.5000 ⇒ 0.7032 ✗ ⇒ 红）；
② `strength = 1` 必须**真的改了像素** ✓（否则"均值不漂"可以靠"什么都不做"骗过去 ✗）；
③ `strength = 5` 后画面**仍有起伏** ✓（不能是提亮到饱和 ✗）。
**修复后重测（400×300、软边厚涂堆、`height_gain: 24`）**：

| `strength` | 0.5 | 1.0 | 2.0 | 5.0 | 10.0 |
|---|---|---|---|---|---|
| 均值漂移 | −0.0 | −0.0 | −0.1 | +0.1 | **+0.4** |
| 标准差变化 | +0.0 | +0.1 | +0.5 | +1.4 | **+2.2** |

=> **均值不再漂**（原来 strength=5 是 +11 ✗）、**对比单调上升** ✓ ⇒ `strength` 只控制浮雕强弱 ✓。
端到端判据 `tool-relief.mjs` 也更干净：右光 **+8.30** / 左光 **−8.30**（原 7.43 ✓）。

**代价（两面都写）** ✓：**所有用过 `relief` 的画面都会变** ✓（原来偏"整体提亮"、现在偏"真浮雕" ✓）
—— 这是一次**有意的行为变更** ✓，由上面三条判据 ＋ 端到端判据守着 ✓。
