## 二、未完成（**接缝与前提都已写清** ✓）

### 1. ④ below 合成缓存（**最大项** ✓）
* **收益（实测 ✓）**：32 层／16 瓦片合成 **49.6 ms** ✗ ⇒ 命中时 **~30×** 下降 ✓；
  **但**用户的真实工程只有 **6~9 层** ✓ ⇒ 实际收益约 **12 ms/笔** ✓（优先级**下调** ✓）。
* **接缝** ✓：`crates/yanshi-render/src/render.rs:683-717`（自下而上的合成循环 ✓）。
* **硬约束** ✗（第 358 轮教训 ✓）：**命中时不得触发任何额外渲染** ✓ ——
  我尝试"预扫顶层是否不透明"时**把候选层渲了两遍** ✗ ⇒ `render_layer_objects` **有副作用**
  （累加告警 ✓、heal／liquify 等**有状态对象** ✓）⇒ **5 个测试变红** ✗ ⇒ 已撤回 ✓。
* **∴ 唯一干净的路线** ✓：**按 tile 记"该层该 tile 是否处处 alpha==255"** ✓
  （渲染该 tile 时顺手算 ✓、与 tile 缓存**同源失效** ✓ ⇒ 簿记必然与像素一致 ✓）。
* **判据（先立 ✓ 再实现）** ✗：
  ① "簿记说不足 ⇒ **逐像素反查**确实处处 255" ✓（**变异**：簿记**恒为真** ⇒ 红 ✓）；
  ② "用簿记跳过 ⇒ 输出**逐字节相同**" ✓（变异：放宽条件 ⇒ 红 ✓）。

### 2. `store.put` 的 **~1.2 s** ✗（导出剩下的那一块）
* **实测** ✓：724 KB 入 CAS 花 **1224／1247 ms** ✗（≈600 KB/s ✓），而同一进程读＋解析＋组装只要 **75 ms** ✓。
* **两个解释（未选定 ✗）** ✓：① 持久化代价（写盘 ＋ fsync ✓）⇒ **不该省** ✗；
  ② 浪费 ✗ ⇒ 候选：重复哈希、写出后读回、逐块小写、目录 fsync 过多、**临时文件＋改名＋多次 flush**（最像 ✓）。
* **下一步** ✓：在 `store.put` **内部分段记时** ✓（同一招探针 ✓ —— 本仓已**六次一击即中** ✓）。
* **若省，两面已写清** ✗：收益 ≲0.6 s ✓；代价＝**削弱"写完就在盘上"** ✓
  ⇒ **判据必须先立在"数据不许丢"** ✓（"保存返回后立刻杀进程 ⇒ 重开必须完整" ✓；
  **变异**：去掉 fsync ⇒ 判据**是否变红** ✓ —— 不变红才说明它可省 ✓）。

## 三、纪律（本会话用**代价**换来的 ✓）

1. **四道门禁必须在"最后一次编辑之后"跑** ✓ —— 我因此栽**两次** ✗（clippy 内联复杂类型 ✗、fmt 改完没复跑 ✗）。
2. **锚点定位与替换必须用同一个"计数断言"** ✓ —— `ExportStats {` 出现两次 ✗，
   我第二处用 `s.find` ✗（总返回第一次 ✓）⇒ 补丁插进**结构体定义** ✗ ⇒ 12 个编译错误 ✓。

   我先猜"注释位置" ✗ 猜错了 ✓（它是**生成物** ✓）。
4. **要验证长跑作业，就必须停止推送** ✓；但**推"被忽略路径"**（`docs/**`／`*.md`／
   `criteria-known-red.txt` ✓）**不触发 CI** ✓ ⇒ **也不会取消**正在跑的 run ✓ ⇒ **记笔记可随时推** ✓。
5. **改了被多条判据覆盖的机制 ⇒ 必须跑全量判据** ✓ —— 我的参考图校验改动**弄红过三条判据** ✗
   （`tool-reference-overlay` ✓、`tool-example-acceptance` ✓、`browser-reference-overlay` ✓）。
6. **不许用"预渲一遍"换取跳过** ✗ —— 渲染**不幂等** ✓（见第二节 1 ✓）。
