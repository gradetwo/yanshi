# 端到端验收：《戴珍珠耳环的少女》眼睛 + 珍珠（第 254 轮）

需求出处：`~/patch/yanshi-引擎MCP需求建议-20261014.md` 的验收目标 ——
「让 AI 通过 MCP 画出维梅尔级古典油画，**以《戴珍珠耳环的少女》眼睛/珍珠为验证目标**」。

脚本：`scripts/tool-vermeer-study.mjs`（`0` 画出来且可复现／`1` 产品问题／`3` 判不了／`2` 用法错）。
证据图：`docs/design/evidence/vermeer-study.png`（640×640，脚本产出，**全程只用 MCP 落笔，不取任何参考图像素** ✓）。

## 一、结论（先说不好听的）

**工具链通了，画得不像** ✓。

* **通**：12 个步骤里 **11 个成功** ✓，覆盖 P0～P2 的全部关键能力 ——
  纸张底纹(⑭) → 草稿层(⑬) → 正稿勾线(⑬) → 介质落笔(载墨/湿度/纹理) → `color_to` 渐变 ＋
  **光谱混色**(⑯) → 瞳孔/高光 → 珍珠本体与二次反光 → **罩染**(⑩) → **厚涂浮雕**(⑮) → **锚点**(⑫) → 出图；
* **可复现**：整个研究跑**两遍**，640×640 的渲染结果**逐字节一致** ✓（确定性硬约束 ✓）；
* **不像**：见证据图 —— 草稿与墨线是**多边形**（不是眼形 ✗）、虹膜是一个**小点** ✗、珍珠是软灰团 ✓、
  整幅离"维梅尔"很远 ✗。

## 二、不像的原因（**分清"引擎缺"与"编排差"**）

| 现象 | 归因 | 证据 |
|---|---|---|
| 眼形是**多边形** | **编排差** ✓ | `medium_stroke`／`brush_stroke` 都**有 `smooth` 参数**（`medium_stroke` 的可用参数里列着 ✓），而脚本**没用**；控制点也只给了 7 个 ✗ |
| 虹膜是**小点** | **编排差** ✓ | 脚本用 2 个相距 0.04×边长 的点去画"虹膜" ⇒ 那本来就只是一小笔 ✓ |
| 珍珠没有**亮到暗的球感** | **编排差 ＋ 一个真缺口** ✓ | 脚本想用介质路径的 `color_to` 渐变，但介质**不支持** `color_mixing`（见下）✓ |
| 没有任何"形状辅助" | **不是缺口** ✓ | 架构原则就是「**引擎做物理、MCP 做编排**」⇒ 椭圆/球体的控制在**调用方**（AI）手里 ✓ |

## 三、验收**真的**抓到的缺口（1 条，已去重）

```
`medium_stroke` 不接受 `color_mixing`（拼写错误？）；可用参数：layer_id, medium, points, size,
color, smooth, symmetry, load, wetness, texture, object_id
```
=> **P2 ⑯ 的光谱混色只接进了 `brush_stroke` 的 `color_to` 渐变** ✗，
**介质路径（油画/水彩/马克笔/铅笔）画不出光谱混色的渐变** ✗。
这一条正是我在实现 ⑯ 时写下的 follow-up（"考虑在介质/揉合路径也支持 `color_mixing`"）✓，
现在被端到端验收**实测确认**了 ✓ => 它就是下一批的 P1 ✓。

## 四、最重要的一条结论（关于"怎么验收"）

**"维梅尔级"这件事，当前的判据体系**验不了** ✗。

* 我可以自动守的东西：**确定性**（两遍逐字节 ✓）、**硬约束**（4K 一笔 ≤100ms ✓）、
  **参数是否生效**（14 条 `tool-*.mjs` ✓）、**工具链是否走得通**（本脚本 ✓）；
* 我**验不了**的东西：**画得像不像** ✗ —— 这需要**人的眼睛**（或一个独立的、可信的画质评审），
  而不是我这样的自动化脚本 ✓。

=> 所以这个验收目标的正确形态是：**脚本负责"通不通、稳不稳、缺什么"** ✓，
**人负责"像不像"** ✓。本轮把前者做成了可复跑的判据 ✓，后者如实留给人 ✓ ——
**不假装评过** ✗（这与本会话"没实测不写成结论"同一条纪律 ✓）。
