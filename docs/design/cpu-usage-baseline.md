# 附三：**「量化」内部的两分**（决策 ① 的判据）

## 问法

**量化**是首帧的第一或第二大项（**本次 945.6 ms ＝ 49.5%**；**文档 §14.1 另一场景 658.6 ms ＝ 31.0%**）。
**∴ 要不要引入 SIMD**（**如 `wide` ✓）**✗ ⇒ **∴ 取决于**——
**f16 往返**（`quantize_f16` ✓）**占它多少** ✓。

**∴ 逐像素做两件事**：
1. **4 × `quantize_f16`**（**RGBA 各一次**；**f32 → f16 → f32 往返**）
2. **颜色表转换 ＋ 写 4 字节**（`srgb_encode_table` ＋ `linear_premul_to_u8x4_with`）

## 实测（`cargo test -p yanshi-render --release --lib split_probe -- --nocapture`）

```
SPLIT 像素=1048576  f16往返=23.262ms  整条=102.971ms  ⇒ f16占=22.6%
```

| 段 | 耗时 | **占比** |
|---|---|---|
| **f16 往返**（4 × `quantize_f16`） | **23.262 ms** | **★22.6%★** |
| **颜色表转换 ＋ 写 4 字节** | **79.709 ms** | **★77.4%★** |
| **整条** | **102.971 ms** | 100% |

**∴ 口径（**如实 ✓）**：
- **单线程**的比例 ⇒ **∴ 与并行时相同** ✓（**∴ 因为**两条路都是**逐像素独立**的 ✓）
- **∴ 绝对时间**不许**跨机器比较** ✓
- **★ 22.6% 是**上界** ✗** —— **∴ 因为**我的 f16-only 循环里**多做了 4 次浮点累加** ✓
  ⇒ **∴ f16 真实占比**≤ 22.6%** ✓

## 结论（**决策 ①**）

| 方案 | 上限收益 | 代价 | **判断** |
|---|---|---|---|
| **`wide`（SIMD f16）** | **≤ 22.6% × 945.6 ms ≈ 215 ms**（≈ 首帧 11%，**实际更低**） | **让渡舍入控制权** ⇒ 与「**逐位一致**」承诺冲突 | **★ 不做 ★** |
| **放开 `unsafe_code` 手写 SIMD** | 同上 | **`forbid` 降级影响 5 个 crate** ＋ 审计面 | **★ 不做 ★** |
| **优化那 77.4%**（颜色表转换 ＋ 写缓冲） | **上限 ≈ 733 ms**（≈ 首帧 38%） | 需查内存带宽／表查找 | **★ 该做 ★** |

**∴ 判据（**我自己定的，如实遵守 ✓）**：**若** f16 占比 > 40% ⇒ **做 SIMD** ✓
**∴ 实测 22.6% < 40%** ✗ ⇒ **★ 所以**：**不做 `wide`，不放开 `unsafe_code`** ✓ ★
**∴ 转向**那 77.4%** ✗ ⇒ **∴ 它**是**表查找 ＋ 4 次写**型 ✓ ⇒ **∴ 与**「裁剪+存 tile 20%」**同属**内存带宽** ✓。

## 守住它的判据

`crates/yanshi-render/src/rows.rs` 的 `#[cfg(test)] mod split_probe`：
**∴ 它**只断言**测量真的发生了**（**比例落在 5%–95%** ✓）
—— **∴ 唯一**要防的失败模式**是**循环被优化掉**（**那会让比例变成 0** ✓）。
**∴ 不**断言具体比例** ✗ —— **∴ 那**会因机器而抖 ✓。
