# 为什么有几支笔刷被改了名 ✓（大小写冲突 ✗）

**问题** ✓：上游 mypaint-brushes 里同时存在
**`Pen.myb` / `pen.myb`** 与 **`Knife.myb` / `knife.myb`** ✓ ——
它们**内容不同** ✓（是**四支不同的笔刷** ✓），但文件名**只差大小写** ✗。

**为什么必须修** ✗：**macOS 与 Windows 的文件系统大小写不敏感** ✓
⇒ 检出到那些系统上时，同名的那两个会**互相覆盖** ✓ ⇒ **静默少掉两支笔刷** ✗
（"东西在仓库里、用户机器上却没有" ✓ 与"说能用其实不能用"是同一类病 ✓）。

**改法** ✓：这些 `.myb` 里有 **`parent_brush_name`** 字段 ✓（如 `ramon/Pen` ✓）
⇒ **用来源目录当前缀** ✓ —— 与把 mypaint-brushes 子目录扁平化时的规则**一致** ✓
（当时我给子目录里的文件加了目录前缀 ✓，但**漏了这几个顶层重名的** ✗）。

**映射（上游名 → 仓库里的名字 ✓）** ✓：

* `Pen.myb` → `ramon-Pen.myb`
* `pen.myb` → `brushkit-pen.myb`（它的 `notes` 写着来自 **Brushkit v0.6** ✓ —— 用它比 `-2` 有信息量 ✓）
* `Knife.myb` → `ramon-Knife.myb`
* `knife.myb` → `classic-knife.myb`

**另有两条同类纪律** ✓：
1. **仓库里任意两个路径都不许只差大小写** ✓ —— 有守卫测试递归扫全仓库挡住它 ✓
   （`crates/yanshi-server/tests/file_name_case.rs` ✓）；
2. **同一目录下不许重名** ✓ —— 子目录扁平化时已经用目录前缀避开了另一批 ✓；
3. **撞名时怎么起名** ✓（优先级 ✓）：先看 **`parent_brush_name`** 的来源目录 ✓，
   再看 **`notes` / `description`** 里写的来源 ✓，**最后**才用序号 ✓
   —— `pen-2` 这种名字**没有信息量** ✗，用途只有一个：临时占位 ✓。

## 顺带记录：**有一支笔刷在当前引擎下画不出来** ✗

`ramon-Knife.myb`（改名自上游 `Knife.myb` ✓）**无论给不给 `size` 都不出墨** ✗。
**查证** ✓：它的文件内容与上游**逐字节一致** ✓（md5 相同 ✓）⇒ **不是改名造成的** ✓；
`size` 给不给都一样 ✓ ⇒ **也不是尺寸覆盖的问题** ✓。
**原因** ✓：它把 `dabs_per_basic_radius` 设成 **0** ✓ ⇒ 间距按**基本半径**算 ⇒ **趋于无穷** ⇒ **一枚印章都不落** ✗
（它依赖的 `dabs_per_actual_radius` 那套没被用上 ✓）。
**处理** ✓：**保留这支笔刷** ✓（它属于上游资源 ✓，将来引擎支持了就能用 ✓），
并让 `brush_stroke` 在这种情况下**说出原因** ✓ 而不是只报"没有墨" ✗
（否则调用方会以为是自己参数给错 ✓ —— 我第一版的报错正是这样误导的 ✓）。

## 还有一个名字触发了 macOS 的 `._` 规则 ✗：`P._Shade.myb` → `P-Shade.myb` ✓

**问题** ✓：上游有一支笔刷叫 **`P._Shade.myb`** ✓ —— 名字里含 `._` ✓。
**而 macOS 把 `._` 前缀当作 AppleDouble（资源叉）的标记** ✗ ⇒ BSD `cp` 在**递归拷贝**时
把它当成 `PShade.myb` 的旁文件 ✓，于是 `make release` 在 macOS 上报：
```text
cp: found P._Shade.myb, looking for PShade.myb
```
**两处都改** ✓（治标 + 治本 ✓）：
1. **改名** ✓（`P._Shade.myb` → `P-Shade.myb` ✓，去掉触发条件 ✓）；
2. **打包不再用 `cp -R` 拷资产** ✓ —— 改成**逐文件拷贝** ✓、**跳过 `._*` 与 `.DS_Store`** ✓、
   并且**拷完核对数量** ✓（少了就**当场失败** ✗）。理由 ✓：递归拷贝的怪癖**不该能让我们少文件** ✗；
   而"产物里少东西却没人知道"正是本项目反复抓的一类病 ✓。
