# 纹理来源与许可 —— **CC0 1.0** ✓（公共领域贡献 ✓，无需署名 ✓、可商用 ✓）

这些纹理由 `scripts/fetch-textures.sh` 从 **ambientCG** 抓取：
<https://ambientcg.com/> ✓，许可证说明见 <https://ambientcg.com/license/> ✓。
抓的是各资产的 **1K-PNG** 变体里的**颜色贴图**（Color ✓）。

**本目录**在 git 里** ✓（实测 `git ls-files assets/textures/` = **11 个** ✓）—— 所以
**克隆下来就有** ✓、**发布包也带着** ✓（`scripts/package-release.sh` 会把它装进
`share/yanshi/textures/` ✓，而且**源目录不在就打包失败** ✗ ⇒ 这是**有意**的 ✓）。

**那 `scripts/fetch-textures.sh` 是干什么的** ✓：需要**更多/别的**纹理时用它联网抓 ✓ ——
它写进**同一个目录** ✓，但本地新增的那些**不会**自动进 git ✗（与上面那 11 个**不同** ✓）。

**★ 2026-10-15 更正 ✗→✓ ★**：这里原来写着「**本目录不在 git 里** ✗ ⇒ 它是运行时缓存」✓ ——
**那句话与仓库不符** ✗（git 里就有这 11 个 ✓）。我（AI）曾据此在验收档里推出
"离线拿不到纹理" ✗，**也是错的** ✓ ⇒ 两处都已按实测改正 ✓（见
`docs/design/vermeer-acceptance.md` §33 ✓）。

**为什么只收 PNG** ✓：本项目的像素解码器是**自己写的** ✓、只解 PNG ✗
（JPEG / WebP 会被**明确拒绝**并说明原因 ✓）⇒ 抓 PNG 变体是为了"抓到就能用" ✓。

## 本目录里的 4 张 `Tile*128.png`（2026-10-15 加 ✓）

**为什么加** ✓：需求文档 P1 ⑦ 的另一条路是"**可平铺纹理资产**" ✓ ——
原目录里的 `Cardboard*`／`Paper*` 是 **ambientCG 的 1K-PNG** ✓（1024² ✓，每张 0.6–2 MB ✓）
⇒ 它们**本身也是无缝的** ✓（实测边缘差 ≈ 内部噪声 ✓），但**又大又少** ✓。

**这 4 张是什么** ✓：**确定性降采样**的产物 ✓ —— **等距抽样**（每 8 个像素取 1 ⇒ 1024 → 128 ✓，
**不用插值** ✗）＋ zlib 手写的**最小 PNG 编码**（8 位 RGB、无过滤 ✓ ⇒ 与仓库**自写的解码器**相容 ✓）：

| 文件 | 用途 | 大小 |
|---|---|---|
| `TilePaperFine128.png` | 细纹纸（最平的底）| ~8 KB |
| `TilePaperFiber128.png` | 纸纤维（略有起伏）| ~36 KB |
| `TileCardboard128.png` | 纸板（粗一点）| ~28 KB |
| `TileCanvas128.png` | 画布（亚麻感）| ~30 KB |

**放在这里而不是另开目录** ✓（2026-10-15 ✓）：引擎的 `list_textures` **只列
`assets/textures/` ＋ 工作区缓存** ✓ ⇒ 放在别的目录里**引擎看不见** ✗
⇒ 搬进来之后它们就是**真正可选的纹理** ✓（合计约 100 KB ✓）。

**判据** ✓：`scripts/tool-tileable-textures.mjs` 会守这 4 张 ——
① 存在且 ≤ 64 KB ✓；② 是**本仓库解码器能读**的 PNG ✓；③ **可平铺**
（用**接缝的二阶差**与内部比 ✓ —— 一阶差会被"很平滑的"纹理骗过去 ✗，实测见
`docs/design/vermeer-acceptance.md` §32 ✓）。
