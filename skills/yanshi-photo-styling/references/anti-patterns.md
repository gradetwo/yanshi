# 反模式与诊断表（修照片 / 调风格）

## 症状 → 直因 → 改法

| 症状 | 直因（实测/代码口径） | 改法 |
|---|---|---|
| 肤色发绿、发青 | 染色主力是 `split_toning`：它在线性空间做加法偏移，显示空间的轻染量级会被放大 2–4 倍（当年港风/国风/电影/HDR 的 v1 病根）。现行数据已用 `amount` 收敛（亮场景 0.35；暗场景逐预设定档 0.05–0.12）并单独保护红色；残余中招条件是**暗场景素材** + strength 拉满或肤色占比大 | 先降 `strength`；再动保护向旋钮（如国风 `zhuhong` 往高、港风 `teal` 往低）；还重就查这套的 `amount` 定档与场景亮度是否匹配（amount 是固定参数，降 strength 收不掉它本身）；**不要动全局色温**——那会把风格的冷调根基掀掉，肤色没救回来、氛围先没了 |
| 整幅蒙灰纱、发雾 | light 基线风格（小清新/韩系/法式/糖水/田园奶油）又叠了一份全量手工校正，或两份修正段重复落 | 只保留一份校正：要手工校正就 `include_correction: false` 只落风格段；已落的用同一预设再 apply 更新，别叠第二组 |
| 什么风格都「使不上劲」 | 素材本身没有信息（如雾占约九成的雾林图，90% 是白雾） | 这类素材只配做解码验证，**不参与风格评价**，换素材；不要靠加大 strength 从雾里榨风格 |
| 夜景天空发棕发橙 | 胶片复古类暖偏置对夜景格外敏感（v2 白天已定版，夜景仍偏棕，是已知的未完全修透项） | 夜景单独降 strength 与暖度旋钮（`retro_film` 的 `warmth`）；不要用白天的定版参数硬套夜景 |
| 圣托里尼类白墙图暗部成团黑 | Ins 简约一类配方阴影压得重，悬崖/背阴面先死 | 降 strength；或先手工把暗部提回再套；白墙题材优先看 `caution` 里的高光/暗部提示再选套 |
| 暗角吃掉角落细节 | LOMO 类风格的暗角本就重（在风格本性内），但过头就是 strength 与 `vignette` 旋钮双高 | 只降 `vignette` 旋钮复评；降完仍重才降 strength |
| 改了参数、图没变 | ① 看的是预览/缩略图那条缓存水位线，它会落后于 head；② 在另一个文档/图层上 apply 了（确定性 id 只在同一文档同一图层命中） | 先看 apply 响应里的 `updated_object_ids` 确认命中；再用 `export_png` 验证——它是同步重渲、恒完整，响应带 `sha256`，两次导出哈希相同就是真没变（别拿 `rendered_seq` 判断导出完整性，它只管预览水位） |
| 对象越落越多 | 换了 preset_id 又 apply，或换了图层——新一组确定性 id，不与上一组冲突也不会自动撤旧组 | 同一套的微调不会叠加；换风格前先想清要留几组，旧组要撤走既有撤销路径，别指望 apply_preset 帮你清场 |
| 预设对象的效果「被改乱了」 | 手工用 update 工具改过预设对象的参数或 opacity，之后再 apply_preset：参数被整笔全量替换、opacity 重置为 1.0 | 把预设对象当作「由 apply_preset 托管」：要长期保留的手工修改，落在自己另建的调整对象上，不要写进预设对象 |
| 糖水图边缘出现斜切异常 | 嫌疑项是 glow 滤镜（对照实验未定论）；配方默认不带辉光，只有显式给 `glow` 旋钮才打开 | 先把 `glow` 旋钮关回去（不给该旋钮再 apply 一次），边缘恢复则定责辉光，结论记进该套 notes，别带着嫌疑交付 |
| 展开/落成整组被拒 | 展开后某笔参数过不了 `validate_effect`，或同 id 对象已被别的效果占用 | 读 error 原文（会写明哪套预设、哪一笔、什么值）；预览阶段就会报，不要等 apply；同 id 冲突就换图层/文档或先删占用对象 |
| 服务端在导入大 RAW 时被杀 | 约 3300 万像素 RAW 的导入展开内存峰值超过小机器可用量（实测：上传能过、展开被系统杀） | 这张不要在这台机器上硬撞：降尺寸、换大内存机器、或换同风格的其他素材顶格位；撞一次记一次，不要循环重试 |
| 批量落图越来越慢/内存涨 | 每步都产预览 PNG（编码开销）+ 并发渲染叠峰值 | `batch` + `silent: true` 静默驱动、串行推进；中途只用 `preview_every_n_strokes` 放行少量预览 |
| import 带了 raw_options 报错 | 给非 RAW 的 blob 带了 `raw_options`，或服务端是关 raw feature 的构建 | 前者去掉参数；后者换开 `raw` feature 的构建——报错原文都会写是哪种，不要改参数碰运气 |
| 竖拍 RW2 导入后画面横倒 | 服务端对 Panasonic RW2 的 EXIF 方向拾取有缺口（Orientation=8 可能被记为 1），导出不旋转；内核未修 | 导入后先核对 `raw_meta` 方向与画面；横倒就把问题记下来上报，不要在图层上用变换硬掰（会把错误状态写进原子日志）；成册/交付时在呈现层旋转并注明 |

## 顺序纪律

**导入展开 → 校正 → 选风格（先 list） → preview → apply → 看图 → 单变量微调**。
跳步的代价都实测过：没校正就施加风格，问题分不清层；跳过 preview 直接落图，
迭代全靠猜；一次动多个量，结论没法沉淀回配方。

## 什么时候才手搓 ops

只有三种情况离开预设：① 预设基线盖不住的逐张校正问题（严重欠曝、混合光源）；
② 预设之外的局部补笔；③ 在外挂目录里实验**新配方**（验证后升内置）。
手搓时参数口径以 `get_preset` 的展开值和内核参数表为准，尤其记牢：
曝光键是 `ev`；levels 的黑/白点是**输入侧位置**（内核实现是 `(v − black) / (white − black)`），
不是输出侧的「抬黑点」——要 fade/抬黑观感，用 curves 把左端点的**输出**抬起来，不要指望
动 levels.black 得到抬升效果，它只会把暗部往黑里压。且 curves 点与 levels.black 都是
**线性坐标**：配方数据里的点列已过 sRGB EOTF 转换（如小清新 curves 首点是 [0, 0.0049]，
不是显示直觉的 0.06），手写新值必须先转换，别照显示数值抄（著录口径全表见 SKILL.md
「数据著录口径」与设计文档 §9.1）。
（历史教训：`japanese_airy` 的 `fade`、`cinema` 的 `matte` 两个旋钮首版曾错挂在
levels.black 上、描述还写「抬量」，越拧越黑；已于 2026-10-23 改挂 curves 首点并加了
方向守卫测试。这类「名字与方向相反」的旋钮，先用 preview 对比展开值再落图。）
