Yanshi 偃师

AI 네이티브 헤드리스 페인팅 엔진 — 사람과 AI가 같은 캔버스에서 함께 창작하는 도구입니다.

  • 작업은 원자입니다. 모든 편집은 로그에 추가되는 원자이며, 그림은 그 로그를 접은 결과입니다. 실행 취소와 다시 실행은 포인터를 이동시킬 뿐입니다.
  • 하나의 커널, 두 개의 호스트. 같은 Rust 커널이 서버에서는 네이티브로, 브라우저에서는 WebAssembly로 동작하므로 로컬 렌더링과 서버 렌더링은 두 개의 근사치가 아니라 하나의 구현입니다.
  • 패키지는 자기완결적입니다. .yanshi 패키지는 원자 로그와 그것이 참조하는 모든 blob을 담고 있어, 다른 곳으로 가져오면 같은 그림이 재현됩니다.

이 엔진 위에는 MCP 서버와 웹 뷰어가 있어, 에이전트와 사람이 같은 문서를 다룹니다.

설치

미리 빌드된 바이너리를 제공하므로 Rust 툴체인이 필요 없습니다 — Linux x86_64(정적), Intel macOS, Apple Silicon:

curl -fsSL https://raw.githubusercontent.com/gradetwo/yanshi/main/scripts/install.sh | sh

스크립트는 플랫폼에 맞는 릴리스 자산을 찾고, 공식 SHA256SUMS로 SHA256을 검증한 뒤 ~/.local/share/yanshi/<버전>에 풀고, yanshi-serve와 yanshi-mcp의 얇은 래퍼를 ~/.local/bin에 넣습니다. 패키지는 자기완결적입니다. 브러시, 브러시 미리보기, 매체, 팔레트, 텍스처, WASM 커널이 모두 들어 있고, 바이너리는 패키지 레이아웃(bin/…과 share/yanshi/…의 병치)으로 자산을 찾으므로 어디에 풀든 실행됩니다.

yanshi-serve --root ~/paint --doc mydoc --bind 127.0.0.1:8080   # 그런 다음 http://127.0.0.1:8080/ 열기
yanshi-mcp   --root ~/paint --doc mydoc                          # stdio MCP 서버, MCP 클라이언트용
yanshi-mcp   --list-tools --profiles core                        # 도구 목록만 표시

조정 변수: YANSHI_VERSION, YANSHI_PREFIX, YANSHI_BIN_DIR, YANSHI_DRY_RUN=1. 미리 빌드된 패키지가 없는 플랫폼(Linux arm64, Windows)은 소스에서 빌드하거나(cargo build --release -p yanshi-http -p yanshi-mcp 또는 make release), 릴리스 페이지에서 Windows 패키지를 직접 풀어 쓰세요.

빠른 시작

필요한 것은 Rust(rust-toolchain.toml에 고정된 stable 툴체인, rustfmt/clippy 포함)와 make입니다. 브라우저 커널(클라이언트 렌더링)을 쓰려면 rustup target add wasm32-unknown-unknown과 wasm-bindgen-cli 0.2.129도 추가하세요. 없어도 서버는 동작하고 뷰어는 서버에서 렌더링합니다.

git clone https://github.com/gradetwo/yanshi.git
cd yanshi
make dev        # 툴체인이 있으면 WASM 커널을 빌드하고, 빌드 후 서빙 ⇒ http://127.0.0.1:8110/

데이터는 기본적으로 ~/.local/share/yanshi/workspace에 있습니다. 포트나 데이터 루트를 바꾸려면 환경 변수로 전달하세요(make dev는 Make 변수를 레시피에 전달하지 않지만, make serve는 --port를 명시적으로 전달합니다):

PORT=9000 make dev
make serve PORT=9000

푸시하기 전에 make check(포맷, 린트, 테스트)를 실행하세요. 전체 타깃은 make help에 있습니다.

현재 상태

  • 버전 0.3.2, 다섯 개 플랫폼용 미리 빌드된 릴리스 패키지 제공(curl 한 줄, 위 참조). 소스는 GitHub에 있고 make release로 직접 패키징할 수도 있습니다.
  • semantic 도구 그룹은 결정에 따라 예약만 되어 있고 구현되지 않았습니다.
  • 브라우저 측 커널은 빌드 산출물이라 새로 클론한 저장소에는 없습니다. 없어도 오류는 나지 않고 뷰어는 서버 측 렌더링으로 돌아갑니다.

이름의 유래

옌스(Yanshi)는 『열자』 「탕문」에 등장하는 장인으로, 노래하고 춤추는 기계 인형을 만듭니다. 원문은 다음과 같습니다:

周穆王西巡狩，越昆侖，不至弇山。反還，未及中國，道有獻工人名偃師，穆王薦之，問曰：「若有何能？」偃師曰：「臣唯命所試。然臣已有所造，願王先觀之。」穆王曰：「日以俱來，吾與若俱觀之。」翌日，偃師謁見王。王薦之曰：「若與偕來者何人？」對曰：「臣之所造能倡者。」穆王驚視之，趨步俯仰，信人也。巧夫，顉其頤，則歌合律；捧其手，則舞應節。千變萬化，惟意所適。王以為實人也，與盛姬內御並觀之。技將終，倡者瞬其目而招王之左右侍妾。王大怒，立欲誅偃師。偃師大懾，立剖散倡者以示王，皆傅會革木膠漆白黑丹青之所為。王諦料之，內則肝膽心肺脾腎腸胃，外則筋骨支節皮毛齒髮，皆假物也，而無不畢具者。合會復如初見。王試廢其心，則口不能言；廢其肝，則目不能視；廢其腎，則足不能步。穆王始悅而歎曰：「人之巧乃可與造化者同功乎！」詔貳車載之以歸。夫班輸之雲梯，墨翟之飛鳶，自謂能之極也。弟子東門賈、禽滑釐聞偃師之巧以告二子，二子終身不敢語藝，而時執規矩。

출처: 중국철학서전자화계획 『열자』 「탕문」. 여기서는 간체자로 옮겨 적었습니다.

빌려올 가치가 있는 것은 솜씨가 아니라 구조와 동작이 분리된다는 점입니다. 열어 보면 노래하고 춤추는 인형은 가죽, 나무, 아교, 옻, 안료일 뿐입니다. 심장, 간, 신장을 빼면 말하지 못하고, 보지 못하고, 걷지 못합니다. 다시 합치면 처음과 같아집니다.

원문의 끝은 사람의 솜씨가 조물주에 견줄 만하다는 목왕의 감탄입니다. 우리는 그렇게 주장하지 않습니다. 이 프로젝트는 도구가 어떻게 만들어졌는지를 적고, 할 수 없는 것도 할 수 있는 것만큼 솔직히 적습니다.

抽出裤衩里的猴皮筋，做成弹弓打你们家玻璃。

(팬티 속 고무줄을 뽑아 새총을 만들어 너희 집 유리를 깨겠다.)

bilibili의 클립. 영화의 권리는 원 권리자에게 있습니다.

빌린 것은 농담 속 그 동작, 즉 손닿는 재료로 쓸 수 있는 것을 만드는 것입니다. 프로젝트의 태도도 같습니다. 구조를 적고, 되는 것은 쓰고, 안 되면 안 된다고 말합니다.
